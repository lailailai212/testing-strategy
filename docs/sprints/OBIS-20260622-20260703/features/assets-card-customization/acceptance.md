## Story AC

1.（AC-01）用户在 Assets 页删除**非必填、可删除**的卡片时，该卡片区块应从页面**移除**。

2.（AC-02）用户删除**内置卡片**时，系统应**隐藏**该卡片且**不清空**其已有内容。

3.（AC-03）已被用户删除（隐藏）的卡片，**创建 Product Version 时不会纳入**该 Module。

4.（AC-04）用户点击删除卡片时，须弹出**二次确认**；文案为 **Are you sure you want to delete this asset type?** / **确定要删除该资产类型吗？**

5.（AC-05）卡片内资产**被引用**时，该卡片**无法删除**，删除按钮**置灰**。

6.（AC-06）用户通过新增入口添加卡片时，可选择「**当前未启用的内置卡片类型**」或「**自定义**」（自定义编辑器见 Story #603）。

7.（AC-07）**内置卡片类型唯一**：已存在的内置类型**不可重复添加**，且**无需填写名称**。

8.（AC-08）**自定义卡片**可添加多张，各自独立；创建时**名称必填**。

9.（AC-09）**内置卡片**删除后再次加回，原有数据应**原样恢复**。

10.（AC-10）**自定义卡片**删除后再次加回，数据**不会保留**；删除时**清除引用关系**。

11.（AC-11）Assets 卡片有**固定排序**；增删卡片**不改变**其余卡片的相对位置。

12.（AC-12）被删除后**加回**的卡片应回到其**固定位**，**不追加到页面末尾**。

13.（AC-13）卡片排序规则为：**内置卡片在前**，**自定义卡片**按创建顺序排在内置卡片之后。

14.（AC-14）当卡片**已被创建到 Version**，或卡片中资产**被其他资产引用**时，该卡片删除操作**置灰**，**无法删除**。

## 测试点

> **来源**：覆盖 Story AC 时填实际 AC 编号（如 `AC-01`；多条用逗号分隔）；否则填 `需求描述` 或 `QA扩展`。

### Assets — 删除卡片（G-1）

| TP-ID | 来源 | 优先级 | 测试点 |
|-------|------|--------|--------|
| TP-AST-DEL-01 | AC-01 | P0 | 对**非必填、可删除**卡片（如 Other Module 下非模板锁定卡）执行删除并确认后，该卡片区块从 Assets 页面**移除** |
| TP-AST-DEL-02 | AC-02 | P0 | 删除**内置卡片**后，页面不再展示该卡片，但**不触发数据清空**（为隐藏而非物理删除） |
| TP-AST-DEL-03 | AC-02 | P0 | 隐藏的内置卡片通过「新增 → 未启用的内置类型」加回后，**删除前已有数据仍可访问**（与 AC-09 联动） |
| TP-AST-DEL-04 | AC-03 | P0 | 已删除（隐藏）的卡片，创建 Product **Version** 时**不会纳入**该 Module 的版本内容 |
| TP-AST-DEL-05 | AC-04 | P0 | 点击卡片删除时**弹出二次确认**，不直接删除 |
| TP-AST-DEL-06 | AC-04 | P0 | 确认弹窗文案：英文 **Are you sure you want to delete this asset type?**；中文 **确定要删除该资产类型吗？** |
| TP-AST-DEL-07 | AC-04 | P0 | 二次确认点击**取消**，卡片保留，不执行删除 |
| TP-AST-DEL-08 | AC-05 | P0 | 卡片内**密钥或证书已被引用**时，删除按钮**置灰**，无法删除 |
| TP-AST-DEL-09 | AC-14 | P0 | 卡片**已被创建到某一 Version** 时，删除按钮**置灰**，无法删除 |
| TP-AST-DEL-10 | AC-14 | P0 | 卡片中资产**被其他资产引用**时，删除按钮**置灰**，无法删除 |
| TP-AST-DEL-11 | AC-01, 需求描述 | P0 | **Story #601 模板不可删除项**（如 Matter 8 张内置卡、SE Module 的 SE 卡）删除按钮**置灰**，优先级高于「非必填可删」 |
| TP-AST-DEL-12 | QA扩展 | P1 | 同时满足多种删除限制（如既被引用又在 Version 中）时，删除仍置灰，无异常提示 |
