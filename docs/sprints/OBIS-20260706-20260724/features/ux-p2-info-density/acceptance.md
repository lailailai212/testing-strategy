# Story: 【体验优化P2】提高整体信息密度

**模式**: Large（跨侧栏 + 全站列表行高 + 浮窗字号 + Product Assets 字号例外；附表多页面，需独立测试点与抽样覆盖）

> 设计像素：菜单高度、通用列表行高以飞书附表/设计稿为准（正文仅明确浮窗 12px、Assets 相关列表字号 13）。

---

## Story AC

1.（AC-01）用户浏览系统左侧菜单栏时，菜单选项高度应符合信息密度调整后的设计规格（对照设计稿），选项文案与导航功能不受影响。

2.（AC-02）用户打开需求附表所列的各业务列表时，列表**表头**与**数据行**行高应符合调整后的设计规格，列表数据与操作能力不受影响。

3.（AC-03）用户触发**黑色浮窗**（如 Tooltip/深色气泡）时，浮窗内文字字号应为 **12px**，文案内容正确可读。

4.（AC-04）用户在 Product **Assets** 页、**查看 Version 的 Assets**、**创建 Version 的 Assets** 中打开相关列表时，列表文字字号应为 **13**（相对通用列表更小），且行高仍符合本 Story 列表密度规格。

---

> **来源**：覆盖 Story AC 时填实际 AC 编号；否则填 `需求描述` 或 `QA扩展`。  
> **优先级口径**：P0 = 全局规则与各模块代表列表冒烟；P1 = 附表内其余列表/详情子列表；P2 = 中英文、缩放边缘。  
> **验收方式**：对照设计稿/开发实现量测（DevTools computed style 或视觉对照）；功能回归以「可正常加载、筛选、翻页、行内操作」为准。
