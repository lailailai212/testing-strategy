# Story: 【自注册】002-01 — Demo 数据预设编排

**来源**: [飞书项目 User Story #7007110712](https://project.feishu.cn/obis/userstory/detail/7007110712)  
**空间**: OBIS (`obis`)  
**编号**: 575 | **优先级**: Must | **Epic**: OBIS自注册  
**模式**: Large（触发/排除/重试/无感知/删除不重建 + 模块内串行与跨模块依赖，规则多；原 AC-02 已删除）  
**同步**: 2026-07-14 评论 — KMS/PKI/工厂互相独立；链路内上一级失败则下一级不开始；产品版本依赖 KMS+PKI

## Story AC

1.（AC-01）自注册 Tenant 创建成功后，系统应异步触发 Demo 预设任务。

2.（AC-03）FM / Vault / PM 任一预设失败时，应自动重试 3 次（间隔 30 秒）；全部失败仍不阻塞用户使用系统。

3.（AC-04）用户对 Demo 预设过程应完全无感知（无阻塞等待、无强制进度页）。

4.（AC-05）Demo 资源在列表展示「Demo Data」标签；用户删除后系统不重建。

5.（AC-06）运营后台开通的 Tenant 不触发 Demo 预设。

6.（AC-07）同一 Tenant 生命周期内 Demo 预设仅触发一次，不重复执行。

> **已删除（评论 2026-07-08）**：原 AC-02「三路独立并行、任一失败不影响其他」。  
> **依赖口径（评论 2026-07-14）**：① KMS 密钥；② PKI：根→中间→叶子（上一级不成功，下一级不开始）；③ 工厂：工厂→烧录站（同上）；④ 产品：产品→版本，版本依赖 ①&②；且 ①、②、③ 互相独立，一失败不影响其他模块。

> **模块定义**：KMS = Demo 密钥；PKI = 根/中间/叶子证书链；FM = Cloud Factory + Programming Station；PM = Product + 资源包 + Version（Version 依赖 KMS+PKI）。

### 依赖顺序与失败传播（评论 2026-07-14）

| TP-ID | 来源 | 优先级 | 测试点 |
|-------|------|--------|--------|
| TP-ORCH-DEP-01 | 需求描述 | P0 | **PKI 链路串行**：根证书不成功时，不开始创建中间证书；中间证书不成功时，不开始创建叶子证书 |
| TP-ORCH-DEP-02 | 需求描述 | P0 | **工厂链路串行**：Cloud Factory 不成功时，不开始创建 Programming Station |
| TP-ORCH-DEP-03 | 需求描述 | P0 | **产品链路**：Product 创建后进入 Version；当 KMS 或 PKI 未成功时，**Version 不开始** |
| TP-ORCH-DEP-04 | 需求描述 | P0 | **跨模块独立**：KMS、PKI、工厂三者互相独立——模拟其一失败时，另两个模块仍可按自身规则继续预设成功（不受该失败阻断） |
| TP-ORCH-DEP-05 | 需求描述 | P1 | KMS 失败且 PKI、工厂成功时：Product 可按实现创建，但 **Version 不开始**；工厂与 Station（在工厂成功前提下）不受 KMS 失败影响 |
| TP-ORCH-DEP-06 | 需求描述 | P1 | PKI 失败且 KMS、工厂成功时：同样 **Version 不开始**；KMS 与工厂链路不受 PKI 失败影响 |
| TP-ORCH-DEP-07 | 需求描述 | P1 | PM 侧 Product/Version 预设失败时独立重试，不回滚已成功的 KMS、PKI、工厂资源 |
